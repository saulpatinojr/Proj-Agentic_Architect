# ADR 0006: Commit the npm lockfile and keep dependency CI read-only

- Status: Accepted
- Date: 2026-09-11

## Context

The initial TypeScript workspace used `npm install` in CI without a committed `package-lock.json`. That allowed dependency resolution to vary between runs and left the repository without an auditable exact npm dependency graph.

A one-time bootstrap workflow generated `package-lock.json` on the bootstrap branch. Continuing to let normal CI regenerate and push dependency state would mix validation with repository mutation.

## Decision

1. `package-lock.json` is committed and is the authoritative resolved npm dependency state for the current workspace.
2. Normal CI uses `npm ci --ignore-scripts` and never rewrites dependency state.
3. Package metadata changes must be accompanied by an intentional lockfile update generated by npm.
4. A read-only lockfile validation workflow may recompute package metadata in the runner and fail on drift, but it does not push changes.
5. Dependency updates remain normal reviewed Git changes.

## Consequences

- CI installs are reproducible from the committed lockfile.
- Dependency drift becomes a failing validation concern instead of an automatic repository mutation.
- The one-time bootstrap write-back is no longer part of normal development.
